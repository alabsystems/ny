# External conformance suites

The default `ny-onnx` test suite is hermetic and has no ignored tests. Tests
that need a generated model, a downloaded competition corpus, or accelerator
hardware run as explicit conformance suites through the launcher:

```sh
targo --unverified run -p ny-onnx --bin ny_onnx_conformance -- whisper --lib
targo --unverified run -p ny-onnx --bin ny_onnx_conformance -- avoice --lib
targo --unverified run -p ny-onnx --bin ny_onnx_conformance -- vnncomp
targo --unverified run -p ny-onnx --bin ny_onnx_conformance -- wgpu --lib
```

The launcher runs the suite as a nested `$CARGO test -p ny-onnx --features
<suite features>` (`targo` when `$CARGO` is unset). When the tool is targo it
adds `--unverified` itself, because targo cannot pass the outer lane to a
nested invocation.

The suites are:

- `avoice`: real `speaker_encoder.onnx`, `talker_attention_layer0.onnx`,
  `kokoro_vocoder.onnx`, and `kokoro_duration_predictor.onnx` exports. Set
  `NY_TEST_MODELS_DIR` or place them in the workspace-root `tests/models/`.
- `whisper`: `whisper_tiny_encoder.onnx`, generated by
  `scripts/export_whisper_encoder.py`.
- `vnncomp`: benchmark corpora installed by
  `benchmarks/download_benchmarks.sh`, plus any result artifacts named by an
  individual diagnostic.
- `wgpu`: a compatible live WGPU device. The `avoice-gpu` and `vnncomp-gpu`
  variants combine hardware with the corresponding external corpus.
- `all`: every suite above.

Arguments after the suite name pass to the nested `test`, so `--release`,
target selection, filters, and libtest arguments work normally. Selecting a
suite registers its tests; a missing required file or device is a failure,
never an early return. Unless already set, the launcher sets
`CARGO_BUILD_JOBS`, `RAYON_NUM_THREADS`, and `TOKIO_WORKER_THREADS` to 1 and
`MALLOC_ARENA_MAX` to 2.
